# Cloud attenuation, tropospheric scintillation and NTN-TDL

Each feature is enabled independently in the UL and DL `hapsmod` records.
The example n78 profiles keep all three switches off. RFsim supplies the
actual carrier frequency and sample rate to the model at runtime.

## Cloud attenuation

Set `enable_cloud = 1` and supply `cloud_liquid_water_kg_m2`, the vertical
liquid-water column traversed by the link in kg/m². The default is `0.0`.
ITU-R P.840-9 §3.1 gives the instantaneous slant loss as
`K_L(f) × L / sin(elevation)`, including the frequency correction to the
liquid-water absorption coefficient. The calculation supports 1–200 GHz and
positive elevation. Supply the column for the modeled path when either
terminal lies within or above the cloud layer. The input is held constant for
the run.

## Tropospheric scintillation

Set `enable_scintillation = 1`. The model applies a constant fade depth for the
configured exceedance percentage using ITU-R P.618-14 §2.4.1.

| Parameter | Default | Meaning |
|---|---:|---|
| `scintillation_nwet` | `50.0` | Wet surface refractivity in N-units |
| `scintillation_antenna_diameter_m` | `0.3` | Physical ground antenna diameter in metres |
| `scintillation_antenna_efficiency` | `0.5` | Ground antenna efficiency as a fraction |
| `scintillation_exceedance_percent` | `1.0` | Percent of time the fade depth is exceeded, greater than 0.01 and at most 50 |

The fade-depth formula covers 4–55 GHz and elevation angles of at least 5°.
Below 4 GHz, including the example 3.6192 GHz n78 carrier, the tropospheric
loss is zero under the ITU-R P.619-5 §2.5.2 negligible-loss approximation.
The model covers tropospheric amplitude scintillation. Location-dependent
climatology, ionospheric scintillation and temporal scintillation traces are
outside this implementation.

Cloud and scintillation losses enter the large-scale budget and appear as
`CLOUD` and `SCINT` in the HAPS logs. At 20 GHz and 30°, with a 0.5 kg/m²
liquid-water column and the scintillation inputs above, the standalone check
gives 0.331330 dB of cloud loss and 0.338403 dB of scintillation loss. The
release n78 profiles remain centered at their configured radio frequency.

## NTN-TDL fast fading

Set `enable_fast_fading = 1` and choose the profile explicitly. A/B represent
NLOS and C/D represent LOS. Profile choice is independent of the large-scale
LoS draw.

| Parameter | Default | Meaning |
|---|---:|---|
| `tdl_profile` | `"NTN-TDL-D"` | One of A/B/C/D with the `NTN-TDL-` prefix |
| `delay_spread_s` | `100.0e-9` | Target pre-quantization RMS excess delay spread in seconds |
| `k_factor_db` | omitted | C/D specular-to-total-diffuse power ratio override in dB |
| `tdl_max_doppler_hz` | `30.0` | Local scattering Doppler bandwidth, with zero for a static draw |
| `update_period_s` | `0.001` | Maximum coefficient interpolation interval in seconds |
| `random_seed` | `12345` | Repeatable realization with separate UL and DL streams |

The tap powers and excess delays come from 3GPP TR 38.811 V15.3.0 §6.9.2
(50° reference profiles). They are scaled to unit expected total path power.
For C/D, omitting `k_factor_db` uses the table values; the optional override
rescales diffuse powers relative to the LOS component per TR 38.901 §7.7.6.
Remove the explicit legacy example value `k_factor_db = 11.707` when using
the tabulated values. Delays are scaled to the requested RMS and then rounded
to the nearest sample, so close taps may share a sample. This excess delay is
in addition to the geometric `channel_offset` when propagation delay is on.

Diffuse taps use a finite sum of 16 sinusoids approximating the Jakes spectrum
and C/D include the LOS tone at `0.7 × tdl_max_doppler_hz`. Coefficient
interpolation is anchored to the sample timestamp and limits the update
interval to at most 1/(16 × maximum Doppler), subject to the one-sample
minimum. The configured common `fixed_doppler_hz` applies once to the sum of
all taps when its existing enable switch is on. Instantaneous gain may vary
around the normalized mean. The selected power-delay profile stays fixed
throughout the run.

To try cloud attenuation and NTN-TDL-D at n78, edit the existing keys in both
records of a private `chan.conf` generated by
[make_profile.py](../examples/make_profile.py) and add the two new parameters.
Keep a copy of the baseline profile for comparison.

```text
enable_cloud = 1;
cloud_liquid_water_kg_m2 = 0.5;
enable_scintillation = 1;
enable_fast_fading = 1;
tdl_profile = "NTN-TDL-D";
delay_spread_s = 100.0e-9;
tdl_max_doppler_hz = 30.0;
update_period_s = 0.001;
```

Remove any existing `k_factor_db` entry to use the tabulated NTN-TDL-D powers.
The example exercises the scintillation switch and returns zero tropospheric
loss at n78. The standalone validation also exercises a nonzero fade depth
at 20 GHz. See [Validation](../validation/README.md).
